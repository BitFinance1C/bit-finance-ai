## Что можно предложить

В этом репозитории два типа материалов:

- **Скиллы (навыки)** — лежат в `data/skills/`;
- **Шаблоны промптов** — лежат в `data/prompts/`.

Процесс отправки для них общий (см. «Путь 1» и «Путь 2» ниже), но требования к файлам — разные. Прочитайте раздел, соответствующий тому, что вы отправляете.

---

## Требования к скиллу перед отправкой

Перед тем как предложить скилл, пожалуйста, проверьте:

1. **Скилл создан в БИТ.ФИНАНС** в справочнике «Навыки» и выгружен кнопкой **«Выгрузить навык»**.
2. **Скилл загружается в программу без ошибок.** Лучше всего проверить это на демо-базе БИТ.ФИНАНС: загрузите скилл и убедитесь, что он работает.
3. **Имя файла совпадает с id скилла.** Используйте латинские буквы, цифры и подчёркивания (`_`), без пробелов и специальных символов. Примеры: `find_client.json`, `get_object_id.json`, `last_order.json`.
4. **Если вид обработчика — «Внешняя обработка»**, обязательно приложите одноимённый файл `.epf` вместе с JSON-файлом. Без него скилл не заработает.
5. **Дополнительное описание не обязательно.** Все нужные поля (название, описание, что делает скилл) уже есть внутри JSON-файла. Если хотите, можете добавить пару слов в комментарии к Pull Request — но это не требование.

---

## Требования к шаблону промпта перед отправкой

Перед тем как предложить шаблон промпта, пожалуйста, проверьте:

1. **Промпт создан в БИТ.ФИНАНС** в справочнике «Шаблоны промптов ИИ» и выгружен кнопкой **«Выгрузить промпт в файл»**.
2. **Промпт загружается в программу без ошибок.** Проверьте это на демо-базе: загрузите файл обратно в карточку и убедитесь, что все поля (наименование, краткое описание, метки, содержание) заполнились.
3. **Имя файла читаемое и уникальное.** Используйте латинские буквы, цифры и подчёркивания (`_`), без пробелов и специальных символов. Примеры: `budget_graph.json`, `payment_request_text.json`, `budget_variance_email.json`. Имя файла `index.json` зарезервировано — не используйте его для промпта.
4. **Поле `Наименование` внутри файла совпадает с полем `name` в `index.json`.** Если они расходятся, пользователь увидит в списке одно имя, а после загрузки в карточке — другое.
5. **Промпт не содержит персональных данных и секретов.** Всё, что попадает в репозиторий, становится публичным.
6. **Дополнительное описание не обязательно** — достаточно того, что уже есть в полях `КраткоеОписание` и `Комментарий`.

## Про файл `index.json`

В каждой папке с материалами есть файл **`index.json`** — это «каталог» всех материалов раздела. Он используется программой 1С для автоматического получения списка: пользователь видит перечень с описаниями, выбирает нужный и скачивает только его, не выгружая весь архив.

**Когда вы добавляете новый материал, в `index.json` соответствующей папки нужно добавить запись о нём.** Формат записи зависит от типа материала.

### Скиллы — `data/skills/index.json`

```json
{
  "id": "имя_скилла",
  "name": "Название скилла",
  "description": "Краткое описание: что делает скилл.",
  "handler_type": "Произвольная процедура",
  "file": "имя_скилла.json",
  "epf_file": null,
  "version": "1.0",
  "author": "ваш_ник",
  "tags": ["тег1", "тег2"]
}
```
Пояснения к полям:
- handler_type — одно из значений: "Внешняя обработка", "Отчет", "Произвольная процедура".
- epf_file — имя файла .epf, если есть; иначе null.
- version, author, tags — необязательные поля, можно не заполнять.

### Шаблоны промптов — `data/prompts/index.json`

```json
{
  "file": "budget_graph.json",
  "name": "Дашборд оборотов бюджета",
  "description": "Формирует интерактивный HTML-дашборд по CSV-выгрузке «Обороты бюджета» из 1С…",
  "tags": ["бюджет", "отчет", "дашборд", "визуализация"],
  "version": "1.0",
  "author": "ваш_ник"
}
```
Пояснения к полям:

- `file` — имя JSON-файла промпта (без пути, только имя).
- `name` — должно совпадать с полем `Наименование` внутри файла.
- `tags` — массив строк; держите 5–8 меток, чтобы фильтр по меткам оставался полезным.
- `version`, `author` — информативные поля, можно оставить значения по умолчанию или указать свои.

> У промптов нет `id`, `handler_type` и `epf_file` — это осознанное отличие от скиллов: промпт заменяет текущий элемент целиком, без сопоставления с существующими записями.

Если вам сложно редактировать JSON вручную — не переживайте, мы добавим запись сами. Просто сообщите об этом.

## Путь 1. Через GitHub (Pull Request)

Этот способ подходит, если у вас есть аккаунт на GitHub и вы готовы отправить Pull Request.

1. **Создайте форк репозитория.** На главной странице репозитория нажмите кнопку **Fork** (в правом верхнем углу). Это создаст вашу личную копию репозитория.
2. **Добавьте файлы в свою копию.** В вашем форке перейдите в нужную папку:
   - для скиллов — `data/skills/`;
   - для промптов — `data/prompts/`.

   Нажмите **Add file → Upload files** и перетащите туда ваш JSON-файл (и `.epf`, если он нужен для скилла).
3. **Добавьте запись в `index.json`.** Откройте `index.json` в той же папке (нажмите на него, затем на карандаш), добавьте запись о вашем материале по формату из раздела «Про файл `index.json`» и сохраните.
4. **Сохраните изменения.** Внизу страницы нажмите **Commit changes**.
5. **Создайте Pull Request.** Вернитесь на главную страницу вашего форка, нажмите **Contribute → Open pull request**. В комментарии коротко опишите, что вы добавили (например: «Новый скилл: поиск клиента по ИНН» или «Новый промпт: дашборд оборотов бюджета»).
6. **Дождитесь проверки.** Мы посмотрим ваш Pull Request и напишем, всё ли в порядке. Если нужно что-то поправить — подскажем.

Если что-то на этих шагах непонятно — ничего страшного, используйте Путь 2.

---

## Путь 2. Без GitHub

Если вы не пользуетесь GitHub — это не проблема. Вы можете передать файлы любым удобным для вас способом: через поддержку БИТ.ФИНАНС, по почте или иным каналом, которым вы обычно пользуетесь.

Что нужно сделать:

1. Подготовьте файлы так же, как описано в разделе «Требования к скиллу перед отправкой» или «Требования к шаблону промпта перед отправкой» (JSON-файл, при необходимости — `.epf`).
2. Свяжитесь с нами и передайте файлы. Можно добавить короткое пояснение, что это за материал, — но это не обязательно.
3. Мы сами загрузим файлы в репозиторий, **обновим `index.json`** в нужной папке и сообщим, когда материал появится.

---

## Что происходит после отправки

- Мы проверяем материал: загружаем его в демо-базу БИТ.ФИНАНС, смотрим, что он работает без ошибок и соответствует требованиям.
- Проверка может занять **до недели**. Это вспомогательный инструмент, который мы развиваем для удобства пользователей, а не сервис с жёсткими сроками. Спасибо за понимание!
- Если всё в порядке — материал появится в репозитории, и мы сообщим вам об этом.
- Если что-то нужно поправить — мы напишем, что именно, и подскажем, как это сделать.

---

## Вопросы

Если что-то осталось непонятным — не стесняйтесь спросить. Мы всегда рады помочь и подсказать. Спасибо, что делаете БИТ.ФИНАНС удобнее!

## Требования к скиллу перед отправкой

Перед тем как предложить скилл, пожалуйста, проверьте:

1. **Скилл создан в БИТ.ФИНАНС** в справочнике «Навыки» и выгружен кнопкой **«Выгрузить навык»**.
2. **Скилл загружается в программу без ошибок.** Лучше всего проверить это на демо-базе БИТ.ФИНАНС: загрузите скилл и убедитесь, что он работает.
3. **Имя файла совпадает с id скилла.** Используйте латинские буквы, цифры и подчёркивания (`_`), без пробелов и специальных символов. Примеры: `find_client.json`, `get_object_id.json`, `last_order.json`.
4. **Если вид обработчика — «Внешняя обработка»**, обязательно приложите одноимённый файл `.epf` вместе с JSON-файлом. Без него скилл не заработает.
5. **Дополнительное описание не обязательно.** Все нужные поля (название, описание, что делает скилл) уже есть внутри JSON-файла. Если хотите, можете добавить пару слов в комментарии к Pull Request — но это не требование.

## Про файл `index.json`

В папке `data/skills/` есть файл **`index.json`** — это «каталог» всех скиллов. В нём перечислены все скиллы с их id, названиями, описаниями и именами файлов. Этот файл используется программой 1С для автоматического получения списка доступных скиллов: пользователь видит список с описаниями, выбирает нужный и скачивает только его, не выгружая весь архив.

**Когда вы добавляете новый скилл, в `index.json` нужно добавить запись о нём.** Это несложно — просто скопируйте существующую запись и поменяйте значения полей. Формат записи:

```json
{
  "id": "имя_скилла",
  "name": "Название скилла",
  "description": "Краткое описание: что делает скилл.",
  "handler_type": "Произвольная процедура",
  "file": "имя_скилла.json",
  "epf_file": null,
  "version": "1.0",
  "author": "ваш_ник",
  "tags": ["тег1", "тег2"]
}
```
Пояснения к полям:

- `handler_type` — одно из значений: `"Внешняя обработка"`, `"Отчет"`, `"Произвольная процедура"`.
- `epf_file` — имя файла `.epf`, если есть; иначе `null`.
- `version`, `author`, `tags` — необязательные поля, можно не заполнять.

Если вам сложно редактировать JSON вручную — не переживайте, мы добавим запись сами. Просто сообщите об этом.

## Путь 1. Через GitHub (Pull Request)

Этот способ подходит, если у вас есть аккаунт на GitHub и вы готовы отправить Pull Request.

1. **Создайте форк репозитория.** На главной странице репозитория нажмите кнопку **Fork** (в правом верхнем углу). Это создаст вашу личную копию репозитория.
2. **Добавьте файлы скилла в свою копию.** В вашем форке перейдите в папку `data/skills/`, нажмите **Add file → Upload files** и перетащите туда ваш JSON-файл (и `.epf`, если нужен).
3. **Добавьте запись в `index.json`.** Откройте файл `data/skills/index.json` в вашем форке (нажмите на него, затем на карандаш), добавьте запись о вашем скилле (см. раздел «Про файл `index.json`» выше) и сохраните.
4. **Сохраните изменения.** Внизу страницы нажмите **Commit changes**.
5. **Создайте Pull Request.** Вернитесь на главную страницу вашего форка, нажмите **Contribute → Open pull request**. В комментарии коротко опишите, что вы добавили (например: «Новый скилл: поиск клиента по ИНН»).
6. **Дождитесь проверки.** Мы посмотрим ваш Pull Request и напишем, всё ли в порядке. Если нужно что-то поправить — подскажем.

Если что-то на этих шагах непонятно — ничего страшного, используйте Путь 2.

## Путь 2. Без GitHub

Если вы не пользуетесь GitHub — это не проблема. Вы можете передать файлы любым удобным для вас способом: через поддержку БИТ.ФИНАНС, по почте или иным каналом, которым вы обычно пользуетесь.

Что нужно сделать:

1. Подготовьте файлы так же, как описано в разделе «Требования к скиллу перед отправкой» (JSON-файл, при необходимости — `.epf`).
2. Свяжитесь с нами и передайте файлы. Можно добавить короткое пояснение, что это за скилл, — но это не обязательно.
3. Мы сами загрузим файлы в репозиторий, **обновим `index.json`** и сообщим, когда скилл появится.

## Что происходит после отправки

- Мы проверяем скилл: загружаем его в демо-базу БИТ.ФИНАНС, смотрим, что он работает без ошибок и соответствует требованиям.
- Проверка может занять **до недели**. Это вспомогательный инструмент, который мы развиваем для удобства пользователей, а не сервис с жёсткими сроками. Спасибо за понимание!
- Если всё в порядке — скилл появится в репозитории, и мы сообщим вам об этом.
- Если что-то нужно поправить — мы напишем, что именно, и подскажем, как это сделать.

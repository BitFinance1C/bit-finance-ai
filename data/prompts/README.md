# Шаблоны промптов ИИ для БИТ.ФИНАНС

В этой папке лежат шаблоны промптов (готовых текстовых запросов) для искусственного интеллекта, которые можно загрузить в программу БИТ.ФИНАНС на платформе 1С.

## Что здесь лежит?

Каждый шаблон промпта — это отдельный файл в формате JSON. Имя файла — произвольное, но должно быть читаемым и уникальным в пределах этой папки. Рекомендуется использовать латиницу, цифры и подчёркивания: например, `budget_graph.json`, `payment_request_text.json`, `budget_variance_email.json`.

В отличие от скиллов, у шаблонов промптов нет идентификатора (id), нет вида обработчика и нет внешних обработок (.epf). Промпт — это просто текст с метаданными, который при загрузке подменяет содержимое текущего элемента справочника.

Структура JSON-файла промпта:
```json
{
  "ВерсияВыгрузки": "1.0",
  "Наименование": "Дашборд оборотов бюджета",
  "КраткоеОписание": "Формирует интерактивный HTML-дашборд по CSV-выгрузке «Обороты бюджета»…",
  "Метки": "бюджет; отчет; дашборд; визуализация",
  "Содержание": "# ЗАДАЧА\n…"
}
```
Поля:
- ВерсияВыгрузки — версия схемы файла. Сейчас всегда "1.0". Служит для обратной совместимости при будущих доработках.
- Наименование — то, что пользователь увидит в карточке после загрузки.
- КраткоеОписание — 1–2 предложения о том, что делает промпт. Показывается в списке выбора на форме.
- Метки — строка с метками через точку с запятой (;). Используется для поиска и группировки.
- Содержание — сам текст промпта. Может быть многострочным, переносы хранятся как \n.

## Файл `index.json` — каталог всех промптов

В этой папке есть файл index.json — это «каталог» всех промптов. В нём перечислены все шаблоны с их названиями, описаниями, метками и именами файлов.

Этот файл используется программой 1С для автоматического получения списка доступных промптов: пользователь видит список с описаниями, выбирает нужный и скачивает только его, не выгружая весь архив целиком.

Формат записи:
```json
{
  "file": "budget_graph.json",
  "name": "Дашборд оборотов бюджета",
  "description": "Формирует интерактивный HTML-дашборд по CSV-выгрузке «Обороты бюджета» из 1С…",
  "tags": ["бюджет", "отчет", "дашборд", "визуализация"],
  "version": "1.0",
  "author": "bit-finance"
}
```
Если вы добавляете новый промпт — не забудьте добавить запись о нём в index.json. Формат записи и примеры — в файле CONTRIBUTING.md в корне репозитория.

## Правила именования файлов
- Имя файла — произвольное, но должно быть читаемым и уникальным в этой папке.
- Рекомендуется использовать латинские буквы в нижнем регистре, цифры и подчёркивания (_). Без пробелов и специальных символов.
- Примеры: budget_graph.json, payment_request_text.json, budget_variance_email.json.
- Файл index.json зарезервирован под каталог — не используйте это имя для промпта.

## Как использовать эти файлы?
1. Скачайте нужные файлы:
- Весь набор сразу: нажмите зелёную кнопку Code → Download ZIP в корне репозитория.
- Отдельный файл: откройте его и нажмите кнопку Raw, затем сохраните страницу.
2. Загрузите промпт в БИТ.ФИНАНС через справочник «Шаблоны промптов ИИ» (используйте кнопку загрузки промпта из файла).
3. Или воспользуйтесь встроенной загрузкой из GitHub прямо из карточки промпта — выберите нужный шаблон в списке и нажмите «Скачать».

## Как предложить свой промпт?
1. Создайте шаблон промпта в БИТ.ФИНАНС в справочнике «Шаблоны промптов ИИ».
2. В форме элемента нажмите кнопку «Выгрузить промпт в файл» — программа создаст JSON-файл нужного формата.
3. Переименуйте файл в читаемое уникальное имя по правилам выше (например, budget_graph.json).
4. Убедитесь, что поле Наименование внутри файла и поле name в index.json совпадают — иначе пользователь увидит в списке одно, а после загрузки в карточке другое.
5. Добавьте файл в эту папку (data/prompts/) и не забудьте добавить запись о промпте в index.json.
6. Отправьте изменения через механизм Pull Request. Подробная пошаговая инструкция — в файле CONTRIBUTING.md в корне репозитория.
7. После проверки и одобрения ваш промпт появится в общем наборе.

## Советы по хорошему промпту
- Структурируйте содержание. Заголовки разделов (# ЗАДАЧА, # ВХОДНЫЕ ДАННЫЕ, # ПРАВИЛА РАСЧЁТА, # ФОРМАТ ОТВЕТА) помогают модели не терять контекст.
- Пишите «КраткоеОписание» для пользователя, а не для себя. Это то, что человек увидит в списке выбора — оно должно помогать ему решить, нужен ли ему этот промпт.
- Метки — 5–8 штук. Слишком много меток размывает фильтр: по каждой отдельной метке будет находиться всё подряд.
- Не дублируйте «Наименование» и «КраткоеОписание». В наименовании — существительное («Дашборд оборотов бюджета»), в описании — глагол и результат («Формирует интерактивный HTML-дашборд по CSV-выгрузке…»).
- Не вставляйте в файл персональные данные и секреты. Всё, что попадает в GitHub, становится публичным.
